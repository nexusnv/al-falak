## v1.2.1 — hotfix: finite-real overflow, Qibla self doc

Patch release with no breaking changes.

PyPI: `al-falak==1.2.1` (`import alfalak`). Requires Python `>=3.11`.

### What's fixed

- `require_finite_real` now maps `float()` `OverflowError`/`ValueError`
  (e.g. huge `int`s like `10**1000`) to `ValidationError`, per the
  `AlFalakError` contract. Covers `delta_t`, `yallop_q`/`yallop_zone`,
  `odeh_v`/`odeh_class`, `is_neo_mabims_2021`/`is_mabims_1992`, and
  `LunarCoordinates`.
- `Qibla` self-point docs now state both models return `180.0` at the
  exact self point (was `spherical ~180.0 vs ellipsoidal 0.0`).
- Synced user docs (`qibla.md`, `errors.md`, `api-reference.md`,
  `moon-sighting.md`) to the landed behavior.

### Quality dashboard

- Gates: `black --check src/` → `ruff check src/ tests/` → `mypy src`
  → `pytest --cov-fail-under=95` (CI: Python 3.11–3.14).
- Tests: regression coverage for huge-int `ValidationError` and
  both-models `180.0` self bearing.

### Install & upgrade

```bash
pip install al-falak==1.2.1
```

No action needed unless you passed huge `int`s to moon-sighting helpers
(previously bare `OverflowError`, now `ValidationError`) or relied on the
old Qibla doc wording for the ellipsoidal self point.
