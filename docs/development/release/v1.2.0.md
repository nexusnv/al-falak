## v1.2.0 — phases 4–5: moon-sighting, Hijri converter

One behavioral breaking change from 1.1.0: `Coordinates` is now frozen —
assigning to its fields raises `FrozenInstanceError`. Replace the instance
instead of mutating it (e.g. `coords = Coordinates(new_lat, new_lon)`).
This release completes milestone
phases 4–5 (lunar ephemeris and visibility criteria, Hijri calendars and
sunset bridge) plus the `Coordinates` freeze (#47). Batch/year-table
performance (#61), config deepening (#40), and the magnetic provider
(#55) are explicitly out of scope and stay open for later minors.

PyPI: `al-falak==1.2.0` (`import alfalak`). Requires Python `>=3.11`.

### What's new

**Phase 4 — moon-sighting**

- `LunarCoordinates` (Meeus Ch.47 low-precision Moon position).
- `crescent_geometry_at_sunset` → `CrescentGeometry` (elongation,
  geocentric/topocentric ARCV, azimuth difference, width, illumination,
  moonset lag, moon age; evaluated at local sunset, raises on polar
  no-sunset).
- `delta_t` provider (Espenak polynomial + IERS `override`; lunar path
  only; calibrated 2005–2050, `UserWarning` outside).
- Visibility criteria: `yallop_q`/`yallop_zone`, `odeh_v`/`odeh_class`,
  `is_mabims_1992`/`is_neo_mabims_2021` (topocentric altitude input).

  ```python
  from datetime import date
  from alfalak import crescent_geometry_at_sunset, Coordinates
  g = crescent_geometry_at_sunset(date(2025, 2, 28), Coordinates(3.1390, 101.6869))
  print(g.elongation_deg, g.moon_age_days, g.lag_hours)
  ```

**Phase 5 — Hijri converter**

- `HijriDate` (frozen, ordered, zero-padded `isoformat()`).
- `HijriCalendar` ABC + `get_calendar` factory (`"tabular"`, `"uqu"`,
  `"mabims"`).
- `TabularCalendar` (arithmetic Type IIa / "Kuwaiti" pattern),
  `UmmAlQuraCalendar` (1423H rule at Makkah, 1445H anchor),
  `MabimsCalendar` (Neo-MABIMS 2021 per-country `MY`/`ID`/`BN`/`SG`).
- `gregorian_to_hijri` bridge (civil-date default,
  `change_at_sunset=True` rolls over at Maghrib).
- `OffsetStore` (per-month `"YYYY-MM"` shifts from dict/JSON).
- `hijri` CLI subcommand (two-line `hijri=`/`calendar=` output).

  ```python
  from datetime import datetime
  from alfalak import gregorian_to_hijri, get_calendar
  cal = get_calendar("mabims", country="MY")
  print(gregorian_to_hijri(datetime(2025, 3, 1), calendar=cal))
  ```

  ```bash
  python -m alfalak hijri --date 2025-03-01 --calendar mabims --country MY
  ```

**Fix**

- `Coordinates` is now a frozen dataclass: the shared `MAKKAH`
  singleton cannot be mutated in place (closes #47). Callers that
  assigned to `latitude`/`longitude` must construct a new instance
  instead (raises `FrozenInstanceError` otherwise).

### Install & upgrade

```bash
pip install al-falak==1.2.0
```

Migration from 1.1.0: one behavioral break — `Coordinates` assignment
now raises `FrozenInstanceError` (#47 freeze turns silent `MAKKAH`/
coordinate mutation into a loud error). Replace the instance instead of
mutating it (e.g. `coords = Coordinates(new_lat, new_lon)`). Everything
else is additive; defaults unchanged.

### Known limitations (deferred, not regressions)

- Magnetic declination is a hook, not a lookup (#55 → v2.0.0).
- Method-default precedence + validation deepening pending (#40 → v1.3.0).
- Hijri bulk/year-table + persistent cache pending (#61 → v1.3.0).
- Announced Hijri dates may differ by ±1 day from computed calendars by
  design (use `OffsetStore` for display alignment).
